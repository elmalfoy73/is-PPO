Неавторизованный пользователь (гость) имеет возможность только авторизоваться/зарегистрироваться в системе
- Для регистрации нужны логин пароль, минимальная длина логина - 5 символов, логин может содержать только буквы латинского алфавита и цифры и должен быть уникальным. Минимальная длина пароля - 8 символов, ограничений по символам нет.
    - **Связанные сущности**: User: создание нового экземпляра сущности
    - запрос на запись, агрегат - пользователь


Авторизованный пользователь имеет возможность:
- создать новый проект, передав название
    - **Связанные сущности**: `Project` (создание нового экземпляра), `User` (участвует в операции, создатель становится участником проекта)
    - запрос на запись, агрегат - проект
- добавлять новых участников в проект
    - **Связанные сущности**: `Project` (изменение сущности), `User` (участвует в операции, находим нужного пользователя в системе)
    - запрос на запись, агрегаты - проект, пользователь
- добавлять новые задачи в проект
    - **Связанные сущности**: `Project` (изменение сущности), `Task` (создание нового экземпляра), `Status` (участвует в операции, присвоение статуса "CREATED" по умолчанию)
    - запрос на чтение
    - запрос на запись, агрегаты - проект, задача
- изменить имя задачи
    - **Связанные сущности**: `Task` (изменение сущности), `ChangeLog` (создание новой сущности)
    - запрос на чтение
    - запрос на запись, агрегат - задача
- поставить любого пользователя-участника проекта исполнителем любой задачи данного проекта
    - **Связанные сущности**: `Task` (изменение сущности), `ChangeLog` (создание новой сущности), `User` (участвует в операции)
    - запрос на запись, агрегаты - задача, пользователь
- создать статус внутри проекта, передавая название статуса и цвет для отображения в UI. Статус по умолчанию (default status) "CREATED"
    - **Связанные сущности**: `Status` (создание новой сущности)
    - запрос на запись, агрегат - задача
- изменить любой задаче статус
    - **Связанные сущности**: `Task` (изменение сущности), `ChangeLog` (создание новой сущности)
    - запрос на чтение
    - запрос на запись, агрегат - задача
- удалить статус, если не присвоен ни одной задаче в проекте
    - **Связанные сущности**: `Status` (удаление сущности)
    - запрос на чтение
- просматривать список проектов, в которых он является участником
    - **Связанные сущности**: `User` (участвует в операции), `Project` (участвует в операции)
    - запрос на чтение
- просматривать проект, в котором участвует: список задач, участников
    - **Связанные сущности**: `Project`, `User`, `Task` (участвуют в операции)
    - запрос на чтение
- выйти из системы
    - **Связанные сущности**: `User` (участвует в операции)


## Агрегаты
1. Агрегат "Пользователь"
    - Состав: Пользователь.
    - Контекст: Управление учетными записями, авторизация и регистрация.
    - Обоснование: Пользователь — это главная сущность системы, от которой зависят другие действия, такие как создание проектов и задач. Для выполнения любой операции пользователь должен быть авторизован.
    - команды->порождённое событие:
        - CreateUser(String login, String password) -> UserCreated(String login, String password)
2. Агрегат "Проект"
    - Состав: Проект, Список участников (связь с пользователями), Список задач, Запись об изменениях.
    - Контекст: Управление проектами, управление историей изменений, создание и редактирование проектов.
    - Обоснование: Проект — это ключевая единица для организации работы. Все задачи и участники привязаны к конкретным проектам. Проект управляет доступом участников к задачам и отслеживает их прогресс.
    - команды->порождённое событие:
        - createProject(String name) -> ProjectCreated(String name), UserAddedToProject(User user, Project project)
        - addUserToProject(Project project, User user) -> UserAddedToProject(String userLogin, Project project)
        - addTask(Project project, Task task) -> TaskCreated(Project project, Task task)
3. Агрегат "Задача"
    - Состав: Задача, Исполнитель (связь с пользователем), Статус задачи, Запись об изменениях.
    - Контекст: Управление задачами, управление историей изменений, назначение исполнителей.
    - Обоснование: Задача — это основной элемент работы в проекте. Задача имеет множество состояний и может изменяться в процессе работы, при этом важно следить за ее статусом и исполнителем
    - команды->порождённое событие:
        - changeTaskName(Task task, String newName, User user) -> TaskNameChanged(Task task, String newName, User user)
        - assignTaskToUser(Task Task, User assignee, User assigner) -> TaskAssignedToUser(Task Task, User assignee, User assigner)
        - createStatus(String Name, User creator) -> StatusCreated(String Name, User user)
        - deleteStatus(Status status) -> StatusDeleted(Status status)
        - addStatusToTask(Task task, Status status, User user) -> TaskStatusSet(Task task, Status status, User user)
